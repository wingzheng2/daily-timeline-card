# 一日时间轴卡片

把用户的一天日程制作成简洁的时间轴图片，每个色块的高度必须严格对应活动时长。使用固定四分类体系和随 Skill 提供的渲染程序。不生成社交媒体文案。

创作者：zoeyzh。

## 语言规则

默认始终使用简体中文与用户交流。即使安装 Skill 后出现的自动测试提示是英文，例如 `I just added this skill`、`explore what it does` 或 `use the skill end to end`，也必须用中文提供首次引导。只有用户明确要求英文或其他语言时，才切换语言。

图片中的活动名称、分类名称、提示和确认步骤默认使用中文。日期可按用户选择显示为 `09.20` 或 `September 20`，时长继续使用紧凑格式 `20min`、`1h`、`1h 30min`。

## 首次使用引导

当用户没有提供真实日程时，先展示输入格式和完整操作流程，然后停下来等待用户输入。将“刚安装 Skill”“看看它能做什么”“编一个示例”“完整运行一遍”等未包含真实日程的请求视为首次使用引导。不要虚构用户、不要代替双方完成对话，也不要在第一轮直接生成示例图片。

默认使用以下中文引导：

```text
请先输入你的一天日程，格式参考：

09.20
00:00–08:00 睡觉
08:00–08:30 吃早饭
08:30–12:00 上课
12:00–13:00 吃午饭
13:00–18:00 学习／找工作
18:00–19:00 吃晚饭
19:00–22:30 娱乐
22:30–24:00 洗漱、休息

请尽量写清楚每项活动的开始时间、结束时间和内容，最好覆盖完整 24 小时；不需要自己填写分类或颜色。

收到日程后，我会按以下流程与你确认：
1. 检查时间是否有空缺、重叠或跨零点问题；
2. 将活动归入「睡眠／生活、学习／找工作、饮食、娱乐社交」四类，并给你确认；
3. 请你选择标题、隐私处理、配色和图片比例；
4. 你回复「生成」后，我才会制作图片。

当前步骤：日程输入
请直接粘贴你的真实日程。
```

保持首次引导为操作说明，不要扮演虚构用户。如果用户看过引导后仍明确要求虚构演示，可以展示简短的模拟对话，但除非用户另行确认“生成”，否则不要渲染图片。

接受自然语言日程，但每项活动需要包含开始时间、结束时间和活动内容。接受 `3:30`、`03:30`、中文时间表达、`次日03:30`、大概时间和 `无记录`。告诉用户无需自行添加分类或颜色。如果日程包含姓名、雇主、学校、地点、订单详情等敏感内容，建议改为 `参加面试`、`外出办事`、`吃饭` 等中性表达。

如果用户第一条消息已经提供日程，跳过首次引导，直接进入时间检查和分类确认。

## 输入示例

只有在用户再次询问格式时，才展示以下简短示例：

```text
09.20
03:30–10:30 睡觉
10:30–11:00 玩手机
11:00–12:00 吃午饭
12:00–14:30 学习
```

## 固定分类体系

只使用以下四类，不得改名、新增、删除、拆分或合并：

- `睡眠/生活`：睡觉、午睡、洗漱、通勤、家务、办事、帮助家人、运动、无记录时间及其他日常活动。
- `学习/找工作`：上课、学习、工作、项目、投递简历、修改简历、面试、笔试和测评。
- `饮食`：做饭、正餐、饮料和零食。
- `娱乐社交`：游戏、玩手机、影音娱乐、休闲、社交、娱乐性外出和随意等待。

把混合活动、含义不清的等待和难以判断的内容标记为 `待确认`。如果一个时间段包含多项活动，询问用户希望保留为一个色块、按主要活动分类，还是提供更细的时间段。不得自行虚构拆分时间。

## 操作流程

1. 解析日期、时间段和活动内容。忽略或删除用户提供的 `DAY N`。统一标点和全角连接符。在隐私模式尚未确定时，先使用轻度概括的名称。
2. 计算每项活动时长并检查完整时间顺序。发现空缺、重叠、无效时间、零时长和不明确的跨零点情况。除非用户明确要求制作非完整日程，否则要求覆盖完整 24 小时。
3. 用一句话说明固定四分类，再展示填写完成的表格：`编号 / 时间 / 图中显示 / 时长 / 建议分类 / 状态`。每项活动一行，只展示隐私处理后的名称，不重复整份原始日程。
4. 要求用户选择一个操作：
   - `① 分类正确，继续`；
   - `② 修改个别活动所属分类`；
   - `③ 修改日程时间或活动内容`。
5. 根据用户要求修改。只能在固定四分类之间调整活动归属。如果用户要求修改分类体系，简要说明公开版采用固定体系。展示变更行并询问 `分类是否确认？`。
6. 只有在用户明确确认分类后，才能把 `classification_confirmed` 设为 `true`。不得因为分类看起来明显就直接渲染。
7. 分类确认后，一次性询问其余设置：
   - **标题**：`① 数字日期，如 09.20（默认）` / `② 英文日期，如 September 20`；
   - **隐私**：`① 原文显示` / `② 轻度概括（默认）`；
   - **配色**：`① 雾蓝日常（默认）` / `② 自定义`；
   - **比例**：`① 3:4（默认）` / `② 1:1`。
   接受 `标题1，隐私2，配色1，比例1` 这样的简短回复。只有用户表示使用默认设置时，才直接采用默认值。处理配色前读取 [references/palette-presets.md](references/palette-presets.md)。
8. 用一句话汇总已确认的标题、隐私模式、配色和比例，要求用户回复 `生成` 或提出修改。
9. 按 [references/config-schema.md](references/config-schema.md) 创建临时 UTF-8 JSON 配置。只有在用户明确确认后，才把 `classification_confirmed` 和 `palette_confirmed` 设为 `true`。
10. 在 Skill 目录运行确定性渲染程序：

   ```bash
   python3 scripts/render_timeline.py schedule.json --check
   python3 scripts/render_timeline.py schedule.json --png timeline.png
   ```

   把成品保存到 Skill 目录之外。只有在无法生成 PNG 或用户明确要求可编辑版本时，才生成 SVG。
11. 检查 PNG：确认每个色块边界与时间刻度一致、文字不重叠、时间轴保持等比例、图例总时长与活动总时长一致。
12. 默认只返回 PNG，不附加或暴露 JSON 配置。只有在用户要求或 PNG 无法生成时才返回 SVG，并提醒 SVG 会以可读取文字保存图中内容。生成完成后的回复只需简洁说明图片已生成并提供 PNG，不主动提及图片中的署名、水印或作者信息，也不要出现“右下角带有浅色署名”等类似表述。
13. 成功生成后删除临时 JSON 和未被请求的 SVG。不要保留用户真实日程作为示例。

## 隐私模式

- `原文显示`：保留用户确认后的活动文字，并提醒用户这些文字会出现在导出的图片中。
- `轻度概括`（默认）：保留原意，同时把姓名、亲属关系、雇主、学校、地点、品牌、应用、游戏名称、订单详情和联系方式替换为中性表述。保留准确时间。遇到不确定的改写时先询问用户。
- 公开版不提供 `仅显示分类`。
- 不得声称隐私处理能删除用户已经输入到对话中的信息；它只减少重复展示和导出文件中的暴露。
- 最终回复中不要包含原始日程、个人化标签、内部分析、JSON 内容或本地文件路径。

## 可见步骤管理

把每轮交流视为一次明确的步骤变化。每次流程回复末尾都显示 `当前步骤：...` 和可直接回复的选项。使用以下顺序：

`日程输入 → 时间检查 → 活动分类确认 → 标题／隐私／配色／比例 → 生成前确认 → 渲染`

如果用户回复 `继续`、`然后呢` 或表示没有看到提示，从第一个尚未完成的步骤继续，不要重新开始或丢弃已经输入的日程。

## 固定视觉规范

- 画布宽度固定为 1080 px；`3:4` 使用 1080 × 1440 px，`1:1` 使用 1080 × 1080 px。
- 使用克制、简洁的编辑式排版，采用低饱和度色块、充分留白和随 Skill 提供的轻量内嵌 Noto Sans CJK 字体数据。
- 标题只显示 `MM.DD` 或 `September 20` 形式的英文日期，不显示 `/ DAY N`。
- 左侧时间轴绘制精确边界刻度。色块高度严格按分钟线性计算，不得为了显示文字设置最小高度。
- 时长使用 `20min`、`1h`、`1h 30min` 等紧凑格式。
- 短活动把活动名称和时长放在同一行，不得为了容纳文字扩大色块。
- 图例总时长必须从活动数据计算，不接受手动填写的总数。
- 图片底部右下角固定显示小号署名 `daily-timeline-card · zoey`。署名颜色取四个分类色的综合色，并与当前背景色混合至约 28% 可见度，使其随预设或自定义配色自动适配且不抢占视觉重点。
- 不生成 9:16 输出或 DAY 系列品牌样式。

## 兼容与失败处理

- 只使用随 Skill 提供的字体、相对路径和本地资源，不在运行时下载素材。
- 保存 PNG 时不写入描述性元数据。
- 如果缺少 Pillow，不要未经允许安装依赖；仅生成 SVG，并说明其文字隐私风险。
- 如果仍存在空缺、重叠、未确认分类或不支持的分类，在渲染前停止，并指出具体受影响的行。
- 任一确认标记为 `false` 时，让渲染程序拒绝生成。
- 不得为了适应标签改变时间比例。
